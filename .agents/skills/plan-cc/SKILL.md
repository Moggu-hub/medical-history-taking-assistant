# คู่มือมาตรฐานการร่างแผนพัฒนาอาการนำ (SKILL_PLAN_CC)

> **⚠️ คำสั่งบังคับสำหรับ AI Agent:**
> ต้องอ่านและปฏิบัติตามคู่มือฉบับนี้ทุกครั้งก่อนเริ่มร่างแผนพัฒนาโมดูลอาการนำ (`plan_<cc>.md`) ใหม่ หรือก่อนแก้ไขแผนตามคอมเมนต์ของผู้ใช้

---

## 1. ขั้นตอนบังคับก่อนเริ่มร่างแผน (Pre-Planning Checklist)

1. **ตรวจสอบข้อมูลทะเบียนอาการนำใน `clinical_knowledge_core.js`:**
   - ยืนยันค่า `id`, `schemaCode`, `titleTh`, `titleEn`, `icon`, และ `phase` ที่ลงทะเบียนไว้ใน `CHIEF_COMPLAINTS`
2. **เลือกแม่แบบอ้างอิงหลัก (Golden Standard CCs):**
   - **กลุ่มอาการไม่ใช่อุบัติเหตุ (Non-Trauma):**
     - ยึด **`cc_modules/04_fever.js` และ `cc_modules/04b_fever_new.js` (CC ไข้/หนาวสั่น — Gold Standard UI/UX)** เป็นแม่แบบด้านการลดภาระ UX ในการอ่านข้อความยาวๆ: ใช้ตัวเลือกสั้นกระชับ (2–5 คำ) ที่**ตัดคำอธิบายย่อย (`desc`) ที่ไม่จำเป็นออก**ในข้อที่เข้าใจง่ายอยู่แล้ว, ระยะห่าง `ml-3`, **การควบคุมการแบ่งบรรทัดไม่ให้ตัดกลางคำภาษาไทย (`whitespace-nowrap` รายกลุ่มคำ)**, **ตาราง Responsive Grid 3–4 คอลัมน์ที่วางกล่องแตกกิ่ง (`branch-card`) ไว้ใต้แถวตาราง**, และการใช้**ไอคอนสีพร้อมปุ่มเล็ก `[ ] ไม่มีอาการในหมวดนี้` ที่มุมขวาบน**
     - **จำนวนการ์ดหลักของแต่ละ CC:** กำหนดให้อยู่ในช่วง **2–4 การ์ด (ไม่รวมการ์ดข้อมูลผู้ป่วยเบื้องต้น และการ์ดประวัติสุขภาพ/ยาประจำตัว)** โดยเลือกจำนวนการ์ดตามความเหมาะสมของเนื้อหาในแต่ละ CC (ไม่จำเป็นต้องบีบเหลือ 2 การ์ดทุกอาการนำ หากการแบ่งเป็น 3 หรือ 4 การ์ดช่วยให้จัดกลุ่มคำถามได้ชัดเจนและกวาดสายตาได้สบายตากว่า)
     - ยึด **`cc_modules/01_abdpain.js` (CC ปวดท้อง)** เป็นแม่แบบด้านการซักประวัติความปวด (OPQRST), แถบวัดความปวด Emoji Pain Scale (0–10 พร้อม Touched State ที่คืนค่า `null` เมื่อไม่แตะ), และโครงสร้างรายงานแพทย์
   - **กลุ่มอาการอุบัติเหตุและการบาดเจ็บ (Trauma):**
     - ยึด **`cc_modules/31_traffic_accident.js` (CC อุบัติเหตุจราจร)** เป็นแม่แบบด้านการคัดกรองกลไกการบาดเจ็บแบบ **Dynamic Context-Aware Branching**, การประเมิน **7 ตำแหน่งร่างกาย (Progressive Parent Checkboxes)** พร้อมระบุข้าง (`ซ้าย` / `ขวา` / `ตรงกลาง`), การแยกนิ้วมือและนิ้วเท้า ซ้าย/ขวา (`โป้ง ชี้ กลาง นาง ก้อย`), การระบุ **ชนิดการบาดเจ็บ (`มีแผล` / `ปวด/บวม/ฟกช้ำ` / `ผิดรูป`)** โดย **แยกแถวคำถาม `ด้าน/ข้าง` กับ `ลักษณะบาดเจ็บ` ออกจากกันให้เว้นระยะชัดเจน**, หมวด `2.7 ตำแหน่งอื่นๆ`, การถาม **LMP ในผู้ป่วยหญิง** และ **เวลาที่งดน้ำ/อาหารครั้งสุดท้าย (NPO Time)**

## 2. โครงสร้างหัวข้อมาตรฐานของไฟล์แผน (`plan_<cc>.md`)

> **💡 กฎประหยัด Context & ตรวจทานง่าย:**
> ในไฟล์แผน `plan_<cc>.md` ให้เน้นเฉพาะหลักการทางคลินิก โครงสร้างคำถาม-ตัวเลือก-คำอธิบายย่อย-เงื่อนไขการแตกกิ่ง และเกณฑ์ Red Flag/CDS ที่อ่านตรวจง่าย **ห้ามใส่โค้ด JavaScript หรือ JSON Seed Cases ยาวๆ ลงในไฟล์แผน**

ไฟล์แผนทุกฉบับต้องประกอบด้วย **5 หมวดมาตรฐาน** ดังนี้:

1. **หมวดที่ 1: หลักการทางคลินิกและการออกแบบ UI/UX (Golden UI/UX & Clinical Rationale)**
   - สรุปมิติสำคัญทางการแพทย์ที่แพทย์เวชศาสตร์ฉุกเฉินต้องทราบควบคู่กับหลักการจัดวาง UI ที่สั้นกระชับ กวาดสายตาได้ทันที (กระชับ 4–6 ข้อ)
2. **หมวดที่ 2: โครงสร้างหน้าจอแบบสอบถามฝั่งคนไข้ (Patient UI Architecture)**
   - แผนผัง ASCII สรุปภาพรวม (แบนเนอร์ส่วนต้นเหนือข้อมูลผู้ป่วยเบื้องต้น + การ์ดคำถามหลัก 2–4 การ์ด)
   - **💡 ส่วนต้น (`data-cc-top-banner` — แสดงก่อนการ์ดข้อมูลผู้ป่วยเบื้องต้น):** ข้อความแจ้งเตือนจุดคัดกรอง (เช่น แนะนำย้ายไป CC เด็กตามเกณฑ์อายุ) และข้อแนะนำการปฏิบัติตัวเบื้องต้นระหว่างรอตรวจ (First-Aid Guidance Banner)
   - **CARD 1 – CARD 2 (หรือถึง CARD 4 ตามความเหมาะสม):** ระบุหัวข้อคำถาม, รูปแบบตัวเลือก (`( )` Radio / `[ ]` Checkbox / ช่องกรอก / ปุ่ม `+` Repeater), ข้อความตัวเลือกหลักที่สั้นกระชับพร้อมจุดแบ่งบรรทัดที่ไม่ตัดกลางคำ, `*(คำอธิบายใต้ตัวเลือก: ...)*` เฉพาะข้อที่จำเป็นจริงๆ, ไอคอนสีประจำหมวดคู่ปุ่ม `[ ] ไม่มีอาการในหมวดนี้` มุมขวาบน (ถ้ามี), และเงื่อนไขการเปิดกิ่งย่อยใต้แถวตาราง (`Dynamic Context/Route Filtering`)
3. **หมวดที่ 3: เกณฑ์สัญญาณเตือนวิกฤตฝั่งแพทย์ (Red Flag Detection Summary — No Under, No Over)**
   - สรุปเงื่อนไขการตรวจจับ Red Flags เฉพาะอาการที่แม่นยำ (No Under-triage และ No Over-triage) สำหรับหน้าจอแพทย์ (ยกเลิกการวางแผน Built-in CDS DDx / Workup / ER Orders เนื่องจากใช้ 1-Click AI Consultant ผ่าน API ภายนอกเท่านั้น)
4. **หมวดที่ 4: แนวทางการพัฒนาไฟล์และการเชื่อมต่อระบบ (Implementation Plan)**
   - ระบุชื่อไฟล์โมดูล `cc_modules/XX_<cc_id>.js`, จุดเชื่อมต่อกับ `clinical_knowledge_core.js` และ `index.html`, และหลักการสรุปรายงานแพทย์เมื่อผู้ป่วยกดยืนยันหรือข้ามหมวดคำถาม (Zero Default Bias)
5. **หมวดที่ 5: ตารางตรวจสอบตนเองก่อนส่งแผน (Mandatory Pre-Submission Self-Check Table)**

## 3. กฎเหล็กและบัญชีข้อห้ามในการวางแผน (Planning Anti-Patterns Guardrails)

| รหัส | ข้อห้ามในการวางแผน (Anti-Pattern) | กฎเหล็กที่ต้องปฏิบัติตาม (Mandatory Rule) |
| :--- | :--- | :--- |
| **P-AP1** | **ตัวเลือกยาวเยิ่นเย้อ หรือมัดรวมหลายอาการไว้ในข้อเดียว** (เช่น รวม *น้ำลายฟูมปาก + เหงื่อแตกท่วมตัว + ปัสสาวะ/อุจจาระราด* ไว้ในตัวเลือกเดียว) | ใช้หัวข้อตัวเลือกที่ **สั้น กระชับ (2–6 คำ)** แยกอาการคนละชนิดออกเป็นคนละข้อ และย้ายคำอธิบายขยายความไปไว้ด้านล่างตัวเลือก (`text-[11px] text-slate-500`) เฉพาะข้อที่กลัวคนไข้ไม่เข้าใจ |
| **P-AP2** | **ใส่คำอธิบายเชิงทฤษฎีแพทย์หรือสมมติฐานชื่อโรคในฝั่งคนไข้** (เช่น `(สงสัย...)` หรือ *"อาการคัดหลั่งของร่างกายทำงานมากผิดปกติ มักพบในพิษจากยาฆ่าแมลง"*) | **ห้ามใส่คำอธิบายเชิงวิชาการแพทย์และห้ามใส่ `(สงสัย...)` บนหน้าคนไข้เด็ดขาด** คำอธิบายใต้ตัวเลือกต้องเป็นตัวอย่างอาการที่คนไข้สังเกตหรือรู้สึกได้จริงเท่านั้น |
| **P-AP3** | **ไม่คัดกรองคำถามตามบริบทหรือช่องทางก่อนหน้า (Lack of Context/Route-Aware Filtering)** ทำให้คนไข้ต้องอ่านตัวเลือกที่ไม่เกี่ยวกับตนจำนวนมาก | ต้องออกแบบ **Dynamic Filtering / Context-Triggered Branching** เสมอ เช่น เปิดกิ่งเจาะลึกเฉพาะอาการหรือตำแหน่งที่เลือก และเปิดกิ่งประวัติสตรีเฉพาะเมื่อผู้ป่วยหญิงเลือกอาการหรือความเสี่ยงที่เกี่ยวข้อง |
| **P-AP4** | **รวมหมวดหมู่สาร/สาเหตุสำคัญที่คนไทยคุ้นเคยแยกกันไว้ในข้อเดียว** (เช่น นำ *สุราเถื่อน/ยาดอง* ไปปนกับ *ผลิตภัณฑ์ใช้ในบ้าน* หรือนำ *สารเสพติด* ไปปนกับ *เห็ดพิษ/พืชพิษ*) | แยกหมวดหมู่ที่มีนัยสำคัญทางคลินิกและในบริบทสังคมไทยออกเป็นตัวเลือกอิสระ ไม่ปะปนกัน |
| **P-AP5** | **ลืมตัวเลือก "ไม่ทราบ / จำไม่ได้ / ไม่แน่ใจ" หรือปุ่มเพิ่มข้อมูลซ้ำ (`+`) ขาดคำอธิบายแก่คนไข้** | คำถามเรื่องเวลา/ปริมาณ/โรคหรือยาเดิมต้องมีตัวเลือกกรณี **ไม่ทราบเวลาที่แน่นอน / จำไม่ได้ / ไม่แน่ใจ** เสมอ และปุ่ม `+ เพิ่มช่วงเวลา/รายการ` ต้องมีคำอธิบายกำกับให้คนไข้เข้าใจชัดเจนว่ากดเมื่อใด |
| **P-AP6** | **เพิ่มช่องกรอกข้อความย่อยที่ไม่จำเป็น (Unnecessary Free-Text Clutter)** เช่น ช่องกรอก "รายละเอียดช่วงเวลานี้ (เช่น หลังอาหารเย็น)" ในตารางเวลา | ตัดช่องกรอกย่อยที่ไม่ได้ใช้คำนวณหรือตัดสินใจทางคลินิกออก เพื่อลดภาระการพิมพ์ของคนไข้ |
| **P-AP7** | **ใช้คำเรียกหัวข้อช่องกรอกเป็นคำเทคนิคห้วนๆ หรือมีคำฟุ่มเฟือย** เช่น `<ชนิดสาร>, <ปริมาณ>` หรือ `"หกรด หรือสัมผัสถูกผิวหนัง"` | ใช้ภาษาไทยที่สุภาพ ชัดเจน และสั้นกระชับ เช่น **`ชื่อยา หรือชนิดของสารพิษ`** คู่กับ **`ปริมาณ หรือจำนวนที่ได้รับ`** และใช้คำว่า **`สัมผัสถูกผิวหนัง`** แล้วค่อยยกตัวอย่างด้านล่าง |
| **P-AP8** | **มีอักษรภาษาต่างประเทศแปลกปลอมหลุดปะปน (Foreign Script Typo)** เช่น อักษรเทวนาครี `या` ปนในคำไทย | ตรวจสอบชุดอักษรทั้งเอกสารให้มีเฉพาะภาษาไทย อังกฤษ ตัวเลข และสัญลักษณ์มาตรฐานเท่านั้น |
| **P-AP9** | **วางช่อง `ด้าน/ข้าง` ชิดกับ `ลักษณะบาดเจ็บ` ในบรรทัดเดียว ใช้สรรพนามเยิ่นเย้อ (`ท่าน (หรือผู้ป่วย)`) หรือปล่อยตัวแปรภาษาอังกฤษลงรายงาน** | ในกลุ่ม Trauma 7 ตำแหน่ง ให้แยกแถว `ด้าน / ข้าง` กับ `ลักษณะบาดเจ็บ` ออกเป็นคนละแถวที่มีระยะห่างชัดเจน ใช้ภาษาถามตรงประเด็น (`ในขณะนี้ผู้ป่วย...`) และกำหนดคำแปลภาษาไทยสั้นกระชับสำหรับรายงานแพทย์ครบทุกตัวเลือก |
| **P-AP10** | **ใส่คำอธิบายย่อย (`desc`) ในข้อที่เข้าใจง่ายอยู่แล้ว, แทรกกล่องกิ่งย่อยคั่นกลางจนตารางแตกเป็นแถวเดี่ยว, หรือสร้างแถว `"ไม่มีอาการ...ข้างต้น"` เต็มความกว้างปิดท้ายทุกหมวด** ทำให้ฟอร์มยืดยาวและอ่านยาก | (1) ตัดคำอธิบายย่อย (`desc`) ในตัวเลือกที่เข้าใจง่ายอยู่แล้วออก (2) เรียงตัวเลือกตั้งต้นเป็นตาราง 3–4 คอลัมน์แล้ววางกล่องแตกกิ่ง (`branch-card`) ไว้**ใต้แถวตาราง** (3) ใช้หัวข้อไอคอนสีคู่กับปุ่มเล็ก `[ ] ไม่มีอาการในหมวดนี้` ที่มุมขวาบนในบรรทัดเดียวกัน แทนการเพิ่มแถว `"ไม่มีอาการ..."` เต็มความกว้างทุกหมวด |
| **P-AP11** | **วางแบนเนอร์แจ้งเตือนคัดกรองหรือคำแนะนำเบื้องต้นไว้หลังการ์ด "ข้อมูลผู้ป่วยเบื้องต้น"** ทำให้ข้อมูลผู้ป่วยเบื้องต้นอยู่ห่างจากคำถามอาการนำมากเกินไปจนผู้ใช้หยุดกรอก | แบนเนอร์แจ้งเตือนจุดคัดกรอง (เช่น แนะนำย้ายไป CC เด็ก) และข้อแนะนำการปฏิบัติตัวเบื้องต้นระหว่างรอตรวจ **ต้องอยู่ส่วนต้นสุดก่อนการ์ดข้อมูลผู้ป่วยเบื้องต้นเสมอ** (`data-cc-top-banner="<cc_id>"`) |
| **P-AP12** | **ปล่อยให้ข้อความตัวเลือกในตารางหลายคอลัมน์ตัดบรรทัดกลางคำภาษาไทย** (เช่น `ถ่ายเหลว / ท้อง(ขึ้นบรรทัดใหม่)เสีย`, `มี-เลือดปน`, `ตัว-เหลือง`) | ต้องกำหนดการแบ่งกลุ่มคำ (`whitespace-nowrap` รายวลี) ให้ตัดบรรทัดเฉพาะหลังเครื่องหมาย `/` หรือช่องว่างระหว่างคำเท่านั้น ห้ามตัดกลางคำประสม |
| **P-AP13** | **รายงานแพทย์แสดงคำย่อที่คลุมเครือไม่สื่อความหมาย (เช่น `• ประวัติสตรี: ไม่แน่ใจ`) หรือกลับกันคือใส่คำสร้อยซ้ำซ้อนในหัวข้อที่ชัดเจนอยู่แล้ว (เช่น `• ประวัติโรคความดันเดิม: ไม่แน่ใจประวัติความดันโลหิตสูงเดิม`)** | (1) ในหน้าคนไข้ ใช้คำสั้นๆ ที่เข้าใจได้จากบริบทรอบข้าง เช่น `[ไม่แน่ใจ]` (2) ในรายงานแพทย์ หากหัวข้อกว้าง เช่น `• ประวัติสตรี:` ต้องแปลงเป็น `ไม่แน่ใจสถานะการตั้งครรภ์` เพื่อให้แพทย์เข้าใจทันที (3) **ห้ามใส่คำสร้อยซ้ำซ้อน**ในหัวข้อที่ระบุเรื่องนั้นชัดเจนอยู่แล้ว (เช่น `• ประวัติโรคความดันเดิม: ไม่แน่ใจ`) |
| **P-AP14** | **สร้างข้อมูลสมมติฐานปกติหรือคำปฏิเสธเทียมเมื่อผู้ป่วยกดบันทึกโดยไม่ได้เลือกตอบ (Default Bias on Empty/Unanswered Submit)** | ต้องออกแบบให้แยกแยะระหว่าง **"ผู้ป่วยไม่ได้ตอบหมวดนี้"** (`ไม่ได้ระบุ` / `ผู้ป่วยไม่ได้ระบุอาการร่วมเพิ่มเติม` / `ผู้ป่วยไม่ได้ระบุคำตอบยืนยันในหมวดอาการร่วม`) กับ **"ผู้ป่วยกดยืนยันว่าไม่มีอาการ"** อย่างเคร่งครัด ห้ามตั้งค่าเริ่มต้นเป็น `ปกติ`, `0/10`, `ไม่ได้ตั้งครรภ์`, `ปฏิเสธ` หรือ `ไม่มี` เมื่อไม่ได้กรอก |
