# คู่มือมาตรฐานการร่างแผนพัฒนาอาการนำ (SKILL_PLAN_CC)

> **⚠️ คำสั่งบังคับสำหรับ AI Agent:**
> ต้องอ่านและปฏิบัติตามคู่มือฉบับนี้ทุกครั้งก่อนเริ่มร่างแผนพัฒนาโมดูลอาการนำ (`plan_<cc>.md`) ใหม่ หรือก่อนแก้ไขแผนตามคอมเมนต์ของผู้ใช้

---

## 1. ขั้นตอนบังคับก่อนเริ่มร่างแผน (Pre-Planning Checklist)

1. **ตรวจสอบข้อมูลทะเบียนอาการนำใน `clinical_knowledge_core.js`:**
   - ยืนยันค่า `id`, `schemaCode`, `titleTh`, `titleEn`, `icon`, และ `phase` ที่ลงทะเบียนไว้ใน `CHIEF_COMPLAINTS`
2. **เลือกแม่แบบอ้างอิงหลัก (Golden Standard CCs):**
   - **กลุ่มอาการไม่ใช่อุบัติเหตุ (Non-Trauma):**
     - ยึด **`cc_modules/04_fever.js` (CC ไข้/หนาวสั่น)** เป็นแม่แบบด้านความสวยงามของ UI, ตัวเลือกสั้นกระชับ (2–5 คำ), ระยะห่าง `ml-3`, ตาราง Responsive Grid, และการซ่อน/เปิดกล่องคำถามเจาะลึก (`Progressive Disclosure`)
     - ยึด **`cc_modules/01_abdpain.js` (CC ปวดท้อง)** เป็นแม่แบบด้านการซักประวัติความปวด (OPQRST), แถบวัดความปวด Emoji Pain Scale (0–10 พร้อม Touched State), และโครงสร้างรายงานแพทย์
   - **กลุ่มอาการอุบัติเหตุและการบาดเจ็บ (Trauma):**
     - ยึด **`cc_modules/31_traffic_accident.js` (CC อุบัติเหตุจราจร)** เป็นแม่แบบด้านการคัดกรองกลไกการบาดเจ็บแบบ **Dynamic Context-Aware Branching**, การประเมิน **7 ตำแหน่งร่างกาย (Progressive Parent Checkboxes)** พร้อมระบุข้าง (`ซ้าย` / `ขวา` / `ตรงกลาง`), การแยกนิ้วมือและนิ้วเท้า ซ้าย/ขวา (`โป้ง ชี้ กลาง นาง ก้อย`), การระบุ **ชนิดการบาดเจ็บ (`มีแผล` / `ปวด/บวม/ฟกช้ำ` / `ผิดรูป`)** โดย **แยกแถวคำถาม `ด้าน/ข้าง` กับ `ลักษณะบาดเจ็บ` ออกจากกันให้เว้นระยะชัดเจน**, หมวด `2.7 ตำแหน่งอื่นๆ`, การถาม **LMP ในผู้ป่วยหญิง** และ **เวลาที่งดน้ำ/อาหารครั้งสุดท้าย (NPO Time)**

## 2. โครงสร้างหัวข้อมาตรฐานของไฟล์แผน (`plan_<cc>.md`)

> **💡 กฎประหยัด Context & ตรวจทานง่าย:**
> ในไฟล์แผน `plan_<cc>.md` ให้เน้นเฉพาะหลักการทางคลินิก โครงสร้างคำถาม-ตัวเลือก-คำอธิบายย่อย-เงื่อนไขการแตกกิ่ง และเกณฑ์ Red Flag/CDS ที่อ่านตรวจง่าย **ห้ามใส่โค้ด JavaScript หรือ JSON Seed Cases ยาวๆ ลงในไฟล์แผน**

ไฟล์แผนทุกฉบับต้องประกอบด้วย **5 หมวดมาตรฐาน** ดังนี้:

1. **หมวดที่ 1: หลักการทางคลินิกในห้องฉุกเฉิน (Clinical Rationale)**
   - สรุปมิติสำคัญทางการแพทย์ที่แพทย์เวชศาสตร์ฉุกเฉินต้องทราบ (กระชับ 5–6 ข้อ)
2. **หมวดที่ 2: โครงสร้างหน้าจอแบบสอบถามฝั่งคนไข้ (Patient UI Architecture)**
   - แผนผัง ASCII สรุปภาพรวม (แบนเนอร์คำแนะนำส่วนต้น + 4 การ์ดมาตรฐาน)
   - **💡 ส่วนต้น:** ข้อแนะนำการปฏิบัติตัวเบื้องต้นระหว่างรอตรวจ (First-Aid Guidance Banner)
   - **CARD 1 – CARD 4:** ระบุหัวข้อคำถาม, รูปแบบตัวเลือก (`( )` Radio / `[ ]` Checkbox / ช่องกรอก / ปุ่ม `+` Repeater), ข้อความตัวเลือกหลักที่สั้นกระชับ, `*(คำอธิบายใต้ตัวเลือก: ...)*` เฉพาะข้อที่จำเป็น, และเงื่อนไขการเปิดกิ่งย่อยหรือการกรองชุดคำถามตามบริบท (`Dynamic Context/Route Filtering`)
3. **หมวดที่ 3: เกณฑ์สัญญาณเตือนวิกฤตฝั่งแพทย์ (Red Flag Detection Summary — No Under, No Over)**
   - สรุปเงื่อนไขการตรวจจับ Red Flags เฉพาะอาการที่แม่นยำ (No Under-triage และ No Over-triage) สำหรับหน้าจอแพทย์ (ยกเลิกการวางแผน Built-in CDS DDx / Workup / ER Orders เนื่องจากใช้ 1-Click AI Consultant ผ่าน API ภายนอกเท่านั้น)
4. **หมวดที่ 4: แนวทางการพัฒนาไฟล์และการเชื่อมต่อระบบ (Implementation Plan)**
   - ระบุชื่อไฟล์โมดูล `cc_modules/XX_<cc_id>.js` และจุดเชื่อมต่อกับ `clinical_knowledge_core.js` และ `index.html`
5. **หมวดที่ 5: ตารางตรวจสอบตนเองก่อนส่งแผน (Mandatory Pre-Submission Self-Check Table)**

## 3. กฎเหล็กและบัญชีข้อห้ามในการวางแผน (Planning Anti-Patterns Guardrails)

| รหัส | ข้อห้ามในการวางแผน (Anti-Pattern) | กฎเหล็กที่ต้องปฏิบัติตาม (Mandatory Rule) |
| :--- | :--- | :--- |
| **P-AP1** | **ตัวเลือกยาวเยิ่นเย้อ หรือมัดรวมหลายอาการไว้ในข้อเดียว** (เช่น รวม *น้ำลายฟูมปาก + เหงื่อแตกท่วมตัว + ปัสสาวะ/อุจจาระราด* ไว้ในตัวเลือกเดียว) | ใช้หัวข้อตัวเลือกที่ **สั้น กระชับ (2–6 คำ)** แยกอาการคนละชนิดออกเป็นคนละข้อ และย้ายคำอธิบายขยายความไปไว้ด้านล่างตัวเลือก (`text-[11px] text-slate-500`) เฉพาะข้อที่กลัวคนไข้ไม่เข้าใจ |
| **P-AP2** | **ใส่คำอธิบายเชิงทฤษฎีแพทย์หรือสมมติฐานชื่อโรคในฝั่งคนไข้** (เช่น `(สงสัย...)` หรือ *"อาการคัดหลั่งของร่างกายทำงานมากผิดปกติ มักพบในพิษจากยาฆ่าแมลง"*) | **ห้ามใส่คำอธิบายเชิงวิชาการแพทย์และห้ามใส่ `(สงสัย...)` บนหน้าคนไข้เด็ดขาด** คำอธิบายใต้ตัวเลือกต้องเป็นตัวอย่างอาการที่คนไข้สังเกตหรือรู้สึกได้จริงเท่านั้น |
| **P-AP3** | **ไม่คัดกรองคำถามตามบริบทหรือช่องทางก่อนหน้า (Lack of Context/Route-Aware Filtering)** ทำให้คนไข้ต้องอ่านตัวเลือกที่ไม่เกี่ยวกับตนจำนวนมาก | ต้องออกแบบ **Dynamic Filtering** เสมอ เช่น คัดกรองชุดคำถามอาการผิดปกติตามช่องทางที่ได้รับสารพิษ หรือคัดกรองกลไกอุบัติเหตุตามชนิดยานพาหนะที่เลือกในข้อก่อนหน้า |
| **P-AP4** | **รวมหมวดหมู่สาร/สาเหตุสำคัญที่คนไทยคุ้นเคยแยกกันไว้ในข้อเดียว** (เช่น นำ *สุราเถื่อน/ยาดอง* ไปปนกับ *ผลิตภัณฑ์ใช้ในบ้าน* หรือนำ *สารเสพติด* ไปปนกับ *เห็ดพิษ/พืชพิษ*) | แยกหมวดหมู่ที่มีนัยสำคัญทางคลินิกและในบริบทสังคมไทยออกเป็นตัวเลือกอิสระ ไม่ปะปนกัน |
| **P-AP5** | **ลืมตัวเลือก "ไม่ทราบ / จำไม่ได้" หรือปุ่มเพิ่มข้อมูลซ้ำ (`+`) ขาดคำอธิบายแก่คนไข้** | คำถามเรื่องเวลา/ปริมาณต้องมีตัวเลือกกรณี **ไม่ทราบช่วงเวลาแน่ชัด** เสมอ และปุ่ม `+ เพิ่มช่วงเวลา/รายการ` ต้องมีคำอธิบายกำกับให้คนไข้เข้าใจชัดเจนว่ากดเมื่อใด (เช่น *กรณีมีการทานยา หรือสัมผัสสารซ้ำหลายครั้ง*) |
| **P-AP6** | **เพิ่มช่องกรอกข้อความย่อยที่ไม่จำเป็น (Unnecessary Free-Text Clutter)** เช่น ช่องกรอก "รายละเอียดช่วงเวลานี้ (เช่น หลังอาหารเย็น)" ในตารางเวลา | ตัดช่องกรอกย่อยที่ไม่ได้ใช้คำนวณหรือตัดสินใจทางคลินิกออก เพื่อลดภาระการพิมพ์ของคนไข้ |
| **P-AP7** | **ใช้คำเรียกหัวข้อช่องกรอกเป็นคำเทคนิคห้วนๆ หรือมีคำฟุ่มเฟือย** เช่น `<ชนิดสาร>, <ปริมาณ>` หรือ `"หกรด หรือสัมผัสถูกผิวหนัง"` | ใช้ภาษาไทยที่สุภาพ ชัดเจน และสั้นกระชับ เช่น **`ชื่อยา หรือชนิดของสารพิษ`** คู่กับ **`ปริมาณ หรือจำนวนที่ได้รับ`** และใช้คำว่า **`สัมผัสถูกผิวหนัง`** แล้วค่อยยกตัวอย่างด้านล่าง |
| **P-AP8** | **มีอักษรภาษาต่างประเทศแปลกปลอมหลุดปะปน (Foreign Script Typo)** เช่น อักษรเทวนาครี `या` ปนในคำไทย | ตรวจสอบชุดอักษรทั้งเอกสารให้มีเฉพาะภาษาไทย อังกฤษ ตัวเลข และสัญลักษณ์มาตรฐานเท่านั้น |
| **P-AP9** | **วางช่อง `ด้าน/ข้าง` ชิดกับ `ลักษณะบาดเจ็บ` ในบรรทัดเดียว ใช้สรรพนามเยิ่นเย้อ (`ท่าน (หรือผู้ป่วย)`) หรือปล่อยตัวแปรภาษาอังกฤษลงรายงาน** | ในกลุ่ม Trauma 7 ตำแหน่ง ให้แยกแถว `ด้าน / ข้าง` กับ `ลักษณะบาดเจ็บ` ออกเป็นคนละแถวที่มีระยะห่างชัดเจน ใช้ภาษาถามตรงประเด็น (`ในขณะนี้ผู้ป่วย...`) และกำหนดคำแปลภาษาไทยสั้นกระชับสำหรับรายงานแพทย์ครบทุกตัวเลือก |

## 4. ตาราง Self-Check บังคับท้ายแผนทุกฉบับ (Mandatory Self-Check Template)

ทุกครั้งที่ร่างไฟล์ `plan_<cc>.md` ต้องคัดลอกตารางด้านล่างนี้ไปวางไว้ท้ายแผน และตรวจทานจริงครบทุกข้อก่อนส่งให้ผู้ใช้ตรวจสอบ:

```markdown
## 5. ตารางตรวจสอบมาตรฐานก่อนส่งแผน (Pre-Submission Self-Check)

| รหัส | รายการตรวจสอบ (Checklist Item) | สถานะ |
| :--- | :--- | :---: |
| **SC-1** | ตัวเลือกทุกข้อสั้นกระชับ (2–6 คำ) และแยกอาการคนละชนิดออกจากกัน ไม่มัดรวมกัน (P-AP1) | ✅ |
| **SC-2** | คำอธิบายขยายความอยู่ด้านล่างตัวเลือก และไม่มีคำอธิบายเชิงวิชาการแพทย์หรือ `(สงสัย...)` (P-AP2) | ✅ |
| **SC-3** | มีการคัดกรองชุดคำถามตามบริบท/ช่องทางก่อนหน้า (Dynamic Context/Route Filtering) เพื่อลดภาระการอ่าน (P-AP3) | ✅ |
| **SC-4** | แยกหมวดหมู่สำคัญในบริบทไทยออกจากกันอย่างชัดเจน ไม่ปะปนกัน (P-AP4) | ✅ |
| **SC-5** | มีตัวเลือก "ไม่ทราบช่วงเวลา/จำไม่ได้" และปุ่ม `+` มีคำอธิบายกำกับชัดเจน ไม่มีช่องกรอกย่อยที่เกินจำเป็น (P-AP5, P-AP6) | ✅ |
| **SC-6** | ใช้คำเรียกช่องกรอกที่เป็นธรรมชาติ เข้าใจง่าย และไม่มีคำสร้อยฟุ่มเฟือย (P-AP7) | ✅ |
| **SC-7** | ไม่มีอักษรภาษาต่างประเทศแปลกปลอมปะปน และไม่มีสัญลักษณ์ 🚩 หรือสีแดงในฝั่งคนไข้ (P-AP8) | ✅ |
| **SC-8** | ช่องวันที่ใช้ `data-universal-date="true"` (`dd/mm/yyyy`) และเวลาใช้ `data-universal-time="true"` (24 ชม.) | ✅ |
| **SC-9** | กรณีประเมินบาดแผล 7 ตำแหน่ง: แยกแถว `ด้าน / ข้าง` กับ `ลักษณะบาดเจ็บ` คนละแถวชัดเจน และกำหนดคำแปลไทยกระชับครบทุกตัวเลือก (P-AP9) | ✅ |
```

## 5. กฎ Auto-Immunization สำหรับ `SKILL_PLAN_CC.md`

- เมื่อผู้ใช้คอมเมนต์แก้ไขแผนในประเด็นที่เป็น **หลักการทั่วไปที่ใช้กับ CC อื่นได้ด้วย (Generalizable Planning Rule)**:
  1. AI ต้องแก้ไขไฟล์แผน `plan_<cc>.md` ตามคอมเมนต์ของผู้ใช้ให้เรียบร้อยก่อน
  2. **AI ต้องสรุปประเด็นนั้นสั้นๆ และถามขออนุญาตจากผู้ใช้ก่อนทุกครั้ง** ว่าจะให้นำกฎดังกล่าวไปอัปเดตเพิ่มใน `SKILL_PLAN_CC.md` ด้วยหรือไม่ (ห้ามอัปเดต `SKILL_PLAN_CC.md` โดยไม่ถามผู้ใช้ก่อน)
